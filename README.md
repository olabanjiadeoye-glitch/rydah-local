# Rydah Local

Rydah Local is a Lagos-first local-services marketplace that connects customers with verified service providers. The product includes provider onboarding and identity/liveness verification, quotes, arrival verification, job tracking, Paystack payments, provider earnings/payouts, reviews, notifications, admin controls, and installable web/Android app delivery.

Production web origin: `https://rydahlocal.online`  
Android package ID: `online.rydahlocal.app`

## Stack

- Next.js 16 / React 19
- Supabase Auth, Postgres, Row Level Security and Edge Functions
- Paystack for customer checkout and provider settlement
- Youverify for provider identity/liveness verification
- PWA + Trusted Web Activity (Bubblewrap) for Android packaging
- GitHub Actions for web validation and Android bundle generation

## Local development

Use Node.js 22.

```bash
npm ci
npm run dev
```

Required public web variables:

```text
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
```

Never expose service-role, Paystack secret, signing-key, or Youverify secret values through `NEXT_PUBLIC_*` variables.

## Supabase Edge Function secrets

The deployed backend uses Supabase-managed secrets such as:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `PAYSTACK_SECRET_KEY`
- `RYDAH_PUBLIC_ORIGIN` (production: `https://rydahlocal.online`)
- `YOUVERIFY_SECRET_TOKEN`
- `YOUVERIFY_PUBLIC_MERCHANT_ID`
- `YOUVERIFY_ENVIRONMENT`
- `YOUVERIFY_BASE_URL` when an explicit endpoint is required

Secrets must stay out of the repository.

## Security model

Rydah relies on database enforcement in addition to UI controls.

- RLS is enabled on application tables.
- Database triggers protect provider trust/biometric fields from self-approval.
- Job-update triggers restrict customer/provider state transitions and protected fields.
- Arrival PINs are issued and verified through controlled RPCs.
- Paystack amounts, provider IDs, commission values and payment state are derived/validated server-side.
- Paystack return URLs are generated by the backend from the trusted Rydah origin.
- Authenticated REST and Edge Function calls retry after refreshing an expired Supabase session.
- Web responses include baseline HSTS, anti-framing, MIME-sniffing and referrer protections.

## Verification and payments

Provider biometric verification is required when the platform setting `biometric_verification_required` is enabled. Providers cannot start protected work until the required verification and arrival checks pass.

Payment flow documentation is in [PAYMENTS_SETUP.md](./PAYMENTS_SETUP.md).

Cash is intentionally limited to jobs of ₦5,000 or less. Paystack payment status is verified server-side and by signed webhook handling.

## CI

### Web CI

`.github/workflows/web-ci.yml`

- installs dependencies with `npm ci`
- runs lint as an advisory check while legacy lint debt is being cleaned up
- runs `npm run build` as the blocking production compilation gate

### Android CI

`.github/workflows/android-twa.yml`

- generates the Trusted Web Activity project with Bubblewrap
- installs/validates Android SDK requirements
- builds an unsigned Android App Bundle
- confirms target API 36
- generates the 512×512 Play icon and 1024×500 feature graphic
- publishes CI artifacts/prereleases

Signing details and Play App Signing notes are documented in [release/android/SIGNING_SETUP.md](./release/android/SIGNING_SETUP.md).

## Pre-production checklist

Before public production release:

- confirm Google Play developer-account verification and Play App Signing
- upload the signed AAB and copy the Play app-signing SHA-256 fingerprint into the production Digital Asset Links configuration
- switch/confirm Paystack production credentials and webhook
- switch/confirm Youverify production credentials and permissions
- run a complete customer → quote → arrival → work → payment end-to-end test
- enable Supabase leaked-password protection in Auth settings
- finalise the account-deletion retention/anonymisation operating procedure before processing real deletion requests
- complete Play Data Safety answers using production behaviour, not sandbox assumptions
- reduce the remaining advisory lint debt in controlled batches

## Private material

Never commit:

- Android keystores or signing passwords
- Supabase service-role keys
- Paystack secret keys
- Youverify secret tokens
- real customer/provider credentials or identity documents
